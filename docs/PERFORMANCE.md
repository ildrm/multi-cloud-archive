# Performance evidence

No representative performance benchmark has been completed. The Windows CLI synthetic smoke dataset is UTF-8 `CloudWeave synthetic round trip. یادداشت آزمایشی\n` repeated 10,000 times, 630,000 bytes. On the development Windows x86_64 host it produced 1,399 stored payload bytes and restored exactly. This highly repetitive text is not representative of photos, RAW, media, ZIPs or mixed workloads. No throughput, peak memory, temporary-disk peak, Android battery usage, large-file latency or UI-responsiveness measurement is claimed.

The implementation processes fixed 1 MiB chunks and uploads/verifies one object at a time instead of staging an entire archive. KDF memory is bounded at 64 MiB, manifests at 8 MiB and chunk references at 50,000; source traversal and names also have bounds. These code limits are not observed process RSS. Measure the requested 256 MiB desktop / 128 MiB Android targets with real datasets and runtime overhead before advertising them.

# Security

CloudWeave is experimental and unaudited. The core crypto composition, native secret handling, restore, dependency graph and release channel require independent human review before a production release. No certification or independent audit is claimed. Do not rely on the current build as the sole copy of irreplaceable files.

Report suspected vulnerabilities privately to the repository owner's private security reporting channel if enabled. There is no verified security contact address configured yet; do not put secrets or private archives in public issues. A public disclosure address must be established before a public release.

Desktop tokens are account-scoped in the OS credential store. Failure to access it is an error, with no plaintext fallback. Linux's encrypted fallback and Android Keystore bridge are not implemented. OAuth uses the system browser, PKCE, state and loopback checks; desktop Google and Dropbox flows do not provide Android authorization. HTTP keeps certificate verification, disables redirects, and bounds object/metadata reads. Upload sessions are checked against an allowed Google HTTPS origin before credentials are attached. Diagnostics do not log tokens, codes, signed URLs, keys or passphrases. Secret strings may still exist temporarily in UI/WebView, library and allocator memory; zeroization is best effort and not a defense against malware controlling an unlocked application.

The catalog stores provider identities, display labels, observed quota and job phase in plaintext. Counts, sizes, object timing and recovery-kit local destination hints are visible. Filenames and chunk mappings live in encrypted manifests, not in SQLite or its WAL. The recovery key export is intentionally plaintext and must be stored separately and protected by the user. The app retains original sources. No deletion, GC, active content preview, telemetry, unsigned update execution or remote-code plugins are implemented.

Restore uses a new random directory, validates all manifest paths before writing, uses new files, checks AEAD and keyed chunk identity, and bounds decompression output and window size. Interrupted/failed restores can leave plaintext in a `.cloudweave-partial-*` directory at the selected destination; it is not a completed restore and is not automatically removed. No defense is claimed against a concurrent local attacker replacing newly created directories or against rollback to valid old snapshots. File metadata and empty-directory preservation are incomplete.
